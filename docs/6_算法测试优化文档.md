- 编写日期：2026-11-11。
- 当前状态：邻域尺度、亚像素后置、GPU 窗口批处理、Top-1 候选预算和小图直接精化已完成。爬山对当前小图直达路径不适用，显存常驻试验因性能及内存回退已撤回。20 ms 目标仍未达到。

## 1. 全局约束

- 公共 `Locator`、`BatchTask`、`LocatorConfig` 和结果语义保持不变。内部优化不得缩小调用方请求的 ROI、角度、尺度或 Top-N 范围。
- 金字塔层数沿用当前定义。2 层表示原图加一次 `pyrDown`，各层逐级缩小，不执行放大搜索。
- 500～600 核基准采用常驻对象。建模阶段只执行一次 `initialize`，实时轮次只更换搜索图并调用 `execute`。
- CPU 使用 OpenMP 任务级并行。GPU 计时包含上传、下载和同步，不允许静默回退 CPU。
- 复用现有 `NccMatcher::match`、`CudaMatcher::matchBatch`、粗层邻近抑制和亚像素样本缓存，不引入新依赖。
- Top-16 只用于未进入小图直达路径的 Top-1 搜索，不新增公共配置字段。多目标保留全部粗候选。Top-32 未实施。
- 小图单模型 Top-1 的宽、高均不超过 256 时直接原图精化，保证与单层搜索使用同一完整响应。该内部策略已同步需求和 API 手册。
- 每项先写能够识别旧行为的失败测试，再做最小实现。未通过回归、未实测性能或未复验 MFC 的项目不得勾选。
- 临时探针、原始计时和截图只放 `temp/`。正式交付程序仍输出到 `build/x64/Release/`。
- 每项完成验收和文档同步后再提交。提交需要用户当次授权，提交信息使用中文并包含本文件任务号。

## 2. 重点审查场景

- 粗层排序反转：粗层高分干扰项不得挤掉原图更优目标，由 A1 的 `Pyramid.CoarseOrderReversal` 和新增粗层低排名真目标用例覆盖。
- 重复印刷纹理与多目标：Top-K、邻域合并和爬山不得漏掉独立目标，由 A1、A3、A4 的重复纹理及 Top-N 用例覆盖。
- 非连续行和 ROI：窗口打包、显存缓存不得把 `width` 当作 `stride`，由 A2、A5 的填充行及 ROI 等价用例覆盖。
- 亚像素评分和排序变化：减少精化对象不得改变最终位置、分数及稳定排序，由 A3 的四档亚像素、100 组合成图和 197 对真实数据回归覆盖。
- 常驻对象重初始化及并行执行：显存不得跨任务错用、泄漏或在析构后继续访问，由 A5 的多帧、重初始化、并行和进程退出用例覆盖。

## 3. 优化前基线与问题证据

　　本节描述优化前实现，当前行为及最终结果见第 9 节。

### 3.1 已测性能

| 场景 | 配置 | 实测整体中位数 | 证据性质 |
| --- | --- | ---: | --- |
| 常驻 CPU 500 | 金字塔 1、亚像素 4、20 线程 | 46.0549 ms | `docs/4_测试报告.md` 已记录 |
| 常驻 CPU 600 | 金字塔 1、亚像素 4、20 线程 | 54.6846 ms | `docs/4_测试报告.md` 已记录 |
| 常驻 GPU 500 | 金字塔 1、亚像素 4、20 线程 | 43.2285 ms | `docs/4_测试报告.md` 已记录 |
| 优化前 GPU 600 | 金字塔 2、亚像素 4 | 300 多 ms | 用户 MFC 实测反馈，尚未做分解复测 |
| Sapera 600 | 金字塔 2、亚像素 4、CPU OpenMP | 30～35 ms | 用户提供的参照，不作为本库已通过结果 |

　　测试机为 i7-11800H 和 RTX 3070 Laptop 8 GB。20 ms 目标、i7-12700K、RTX 4060 12 GB 和 Windows 10 仍未完成指定环境验收。后续优化不得把不同机器、不同参数或不同任务数的数值直接横向比较。

### 3.2 金字塔候选放大

　　优化前 `src/PyramidSearch.cpp` 把粗候选的 `maxResults` 设为候选总数，并执行半径 1 的邻近抑制，再对每个保留候选执行一次原图局部搜索，其中包含局部 NCC、局部峰筛选和亚像素复核。

　　以 2 层、118×118 搜索图和 48×48 模板为例，粗层尺寸分别为 59×59 和 24×24，粗响应为 36×36，即 1296 个位置。`coarseMinScore = max(0, minScore - 10)`。默认 `minScore = 0` 时，负 NCC 映射后的 0 分也不会被阈值排除。实际进入精化的数量必须经过邻近抑制后的计数确认，不能把 1296 写成实际精化次数。

　　2 层精化半径为 6。单个候选的原图窗口最大为 61×61，对应 14×14 局部响应。候选密集时，大量重叠窗口会重复计算相同像素。

### 3.3 GPU 调度缺口

　　优化前单次 `CudaMatcher::matchImpl` 每轮都上传搜索图和模板，再下载响应并同步流。金字塔逐候选精化反复走该入口。

　　原有四任务 `CudaMatcher::matchBatch` 只在一次性 `executeBatch` 的单层、无 ROI、固定角度和固定尺度路径使用。常驻 OpenMP 循环中的每个 `Locator::execute`，以及金字塔逐候选窗口精化，都没有复用批量打包。

　　优化前模板 NCC 统计已缓存，模板像素和模板金字塔未常驻显存。搜索图金字塔在每帧 `Locator::execute` 中构建。后续应先测量各项占比，再决定优化顺序内的工作量，不凭总耗时推断单个环节。

## 4. 方案选择与总体顺序

| 方案 | 收益与代价 | 决定 |
| --- | --- | --- |
| 只做爬山法 | 实现局部，能减少细层邻域扫描，但无法解决粗候选数量和逐候选 GPU 同步，重复纹理下还可能陷入局部峰值 | 不单独采用 |
| 只做激进 Top-K | 改动小，可能立即减少精化次数，但粗层排序反转时会漏掉真目标 | 只作为受控试验 |
| 全量改写 GPU 算法 | 可能获得长期收益，但改动面大，当前缺少分解计时，难以判断真实瓶颈 | 暂不从重写开始 |
| 分阶段组合优化 | 先建立证据，再做候选控制、等价批处理和后处理减量，每项可独立撤销 | 采用 |

　　执行顺序如下。前一项未通过正确性回归时，不进入依赖它的下一项。

1. A0 建立双后端金字塔矩阵和分解计时，确认粗候选数、窗口精化次数、传输、同步及亚像素占比。
2. A1 复用现有邻近抑制，试验 Top-16、Top-32 和重叠窗口合并，增加失败时原图回退。
3. A2 用现有 `CudaMatcher::matchBatch` 打包候选窗口，保持逐窗口响应及后续处理顺序一致。
4. A3 将金字塔路径的整数候选筛选与亚像素复核拆开，只在全局候选预筛后执行必要亚像素工作。
5. A4 在保留候选上试验批量 8 邻域爬山，减少细层局部扫描。它只替代局部搜索，不承担全局召回。
6. A5 按实测决定模板及模板金字塔显存常驻，完成双后端、197 对真实数据、100 组合成图、500/600 核和 MFC 最终验收。

## 5. 统一测试口径与通过条件

### 5.1 性能矩阵

　　按用户最新确认，每项优化只使用 README Demo 1 的常驻 OpenMP 方法评估 500 个定位核。固定 Release x64、20 线程、完整搜索图、角度 0、尺度 1、Top-N 1、亚像素 4、金字塔 2。旧实现耗时过长，开发阶段改为预热 5 轮、记录 5 轮，最终验收恢复预热 5 轮、记录 50 轮。快速与完整原始数据分开保存，不混用中位数。600 核不再作为每轮必测项，既有金字塔 1 基准保留作历史对照和功能回归。

| 任务数 | 后端 | 金字塔 | 亚像素 | 用途 |
| ---: | --- | ---: | ---: | --- |
| 500 | CPU | 2 | 4 | 本轮优化前后同口径对比 |
| 500 | GPU | 2 | 4 | 复现并优化用户反馈的高耗时场景 |

　　500 个任务循环复用现有 197 对真实图，不写成 500 对独立真实数据。每轮保存整体耗时和逐任务耗时。汇总报告中位数、均值、P99、建模一次耗时和工作集增量。GPU 另存上传、kernel、下载、同步及批量组数。新增原始文件名包含任务数、后端和金字塔层数，避免覆盖既有基线。

### 5.2 正确性与采纳门槛

- CPU 全量测试、GPU 套件、100 组合成图和 197 对真实数据全部通过。合成图中心误差不超过 1/8 像素，角度误差不超过最终角度步长的一半。
- 等价批处理要求逐响应满足现有 GPU 浮点容差，最终坐标沿用既有阈值，结果顺序不变。
- 197 对真实数据基准用于检测回归，不代表独立人工真值。涉及候选裁减或爬山时，还需增加带独立真值的重复纹理、多目标及粗层排序反转用例。
- 每项与同机、同代码基线、同参数矩阵比较。整体中位数没有改善，或 P99 明显恶化且无法解释时，不保留该优化。
- 候选裁减或爬山引起真实漏检、已知真值超差、结果数量错误时，立即停用该试验并恢复上一通过版本。
- 500 核 20 ms 仍是目标，不是已承诺结果。Sapera 的 30～35 ms 只作尽量接近的参照，不设为硬性指标。正确性、稳定性和边界鲁棒性优先，不得为接近该数值接受漏检或异常。

## 9. 实际执行结果

　　本节记录最终采用的行为和实测。前面的任务步骤保留为方案原文，未逐项勾选的步骤不视为完成。实际执行根据测量调整了顺序，先完成亚像素后置，再完成 GPU 窗口批处理。

### 9.1 已采用修改

- 粗候选位置已经映射到原图尺度，粗层邻近半径同步按金字塔倍率换算。2 层时使用 2，修复相邻粗候选无法合并的问题。
- 新增真正的整数候选提取，不读取亚像素样本缓存。Top-1 分层路径先做整数候选筛选，再对最佳模型执行一次请求档位的原图复核。
- GPU 原图精化窗口复用 `CudaMatcher::matchBatch`。每批 4、64、256、512 的开发对比后保留 256。
- 非小图直达的 Top-1 粗候选最多保留 16 个。多目标恢复保留全部粗候选，不套用 16 个上限。
- 单变换、Top-1、宽和高均不超过 256 的搜索图直接使用原图搜索，不再执行粗层和重复局部窗口。该路径与单层共用同一完整响应及亚像素流程。
