# 搜索匹配定位库开发需求文档（v2.0 已确认稿）

　　本文档合并初步需求和已确认意见，作为开发设计与后续实现的统一依据。需求范围已经明确，可以编写开发设计文档，本文档不要求立即开始算法编码。

　　`reference/sapera_headers/`、`reference/Sapera_SearchTool_文档.md` 和 `reference/manuals/` 用于理解搜索参数、算法机制和结果语义，不作为公共接口、类名、数据结构或二进制兼容的复制标准。

## 1. 项目定位与目标

- 建设一套由公司内部算法团队统一维护和使用的 C++ 搜索匹配定位源码库，替换现有项目中的 Sapera Search Tool 面积法功能。
- 项目仅供内部使用，不考虑商业化交付和外部客户分发。
- 核心算法只交付源代码，由使用方根据操作系统、IDE 和编译器自行组织工程并生成所需库文件。
- 在满足定位精度的前提下，算法效率和搜索速度是第一优先级。
- 本期提供 MFC 演示与评估工具，用于验证代码正确性、测试效率和开展参数试验。
- 调用方可以修改适配代码并重新编译，不要求免重编译替换或业务源代码零改动。

## 2. 交付形态与技术约束

### 2.1 核心算法源码

- 只提供 `.h`、`.cpp` 等源代码文件及必要的测试源码，不交付静态库或动态库。
- 核心代码按可移植方式编写，不依赖 MFC、Windows API 或特定 IDE 的工程文件。
- 已确认开发和验证环境为 Windows 10、Visual Studio 2019。其他平台和 IDE 可以自行编译，但不写成已经验证的环境。
- 语言标准以 Visual Studio 2019 默认的 `/std:c++14` 模式为基线，核心源码不得要求调用方额外选择 `/std:c++17`。
- 算法实现不限于 OpenCV，可自主开发，也可选用合适的开源算法或库，最终以速度、精度和鲁棒性的实测结果为选型依据。
- 允许使用 OpenCV 4 或更高版本，禁止依赖商业视觉 SDK。所选 OpenCV 版本必须支持 Visual Studio 2019，实际验证版本记录在测试说明中。
- 核心算法以同时提供 CPU 和 GPU 加速版本为目标。CPU 版本是通用基线，GPU 版本在具备兼容硬件、驱动和运行时的环境中构建与验证，不得妨碍仅使用 CPU 的环境编译和运行。用户团队现有 GPU 最低为 RTX 4060、12 GB 显存，GPU 设计与验收以此为基础。
- GPU 路径须包含核心匹配计算的 GPU 加速，可以采用 GPU 与 CPU 协同实现。选择 GPU 后不可用时应返回明确错误，不得静默切换为 CPU 并声称使用了 GPU。
- 使用 OpenMP 执行任务级并行。没有 OpenMP 的环境应能使用串行路径编译和运行核心算法。
- 平台或指令集相关优化必须有条件编译保护和通用实现，不能妨碍其他环境编译。

### 2.2 MFC 演示与评估工具

- 工具在 Windows 10、Visual Studio 2019 环境中开发和验证。
- 工具与核心算法分开放置，核心源码不得反向依赖工具代码。
- 工具直接编译并调用同一套核心算法源码，保证测试对象与实际交付代码一致。

### 2.3 接口与维护约束

- 使用本库自有接口，调用工程完成适配后重新编译。
- 接口以简单、清晰、便于内部维护为准，不复刻 Sapera 的类体系和继承关系。CPU、GPU 后端及设备参数可使用本库自有定义，参数名称和取值无需与 Sapera 一致。
- 不强制采用 pImpl、ABI 隔离或隐藏全部内部类型，不承担 Sapera 二进制兼容成本。
- 提供必要的中文注释、单元测试和使用说明。

## 3. 核心功能需求

### 3.1 输入图像与坐标定义

- 输入限定为 8 位单通道灰度图，模板图像与搜索图像使用相同格式。
- 输入接口应能接收图像指针、宽高和行跨度，不能只接受特定 IDE 的图像对象。
- 输出坐标 x、y 对应模板中心在搜索图像中的位置。
- 模板中心按几何中心计算，即连续坐标中的 `(width - 1) / 2`、`(height - 1) / 2`，偶数尺寸模板可以落在半像素位置。

### 3.2 模板匹配定位

- 核心算法采用归一化互相关（NCC）。
- 匹配分数采用 0～100 的百分比语义，分数越高表示匹配程度越高。
- 支持配置分数阈值，低于阈值的结果不返回。
- 模板预处理与搜索执行分开，避免批量任务重复计算可复用的数据。
- 500～600 个定位核的连续实时检测采用常驻对象模式。建模阶段分别完成 `initialize`，实时帧只更换搜索图并并行调用 `execute`，不在实时循环中重复构造对象或初始化模板。
- 一次性 `executeBatch` 保留现有任务语义，不作为常驻实时检测的推荐入口。Sapera 仅作为生命周期和操作逻辑参考，不要求搜索算法、评分或内部表示完全等价。

### 3.3 多角度与多尺度搜索

- 旋转范围和角度步进可配置，例如 ±10°、步进 0.1°。
- 缩放范围和缩放步进可配置，例如 0.9～1.1。
- 搜索范围、步进和金字塔层数以调用方设置为准，内部优化不得擅自缩小范围或降低请求的搜索精度。
- 坐标系采用 x 向右、y 向下的图像坐标系，角度单位为度，正角度按顺时针方向定义。
- `scale = 1` 表示保持模板原始尺寸。

### 3.4 ROI 与尺寸处理

- 支持在搜索图像上设置矩形搜索区域（ROI），只在 ROI 内计算。
- 模板尺寸、搜索图像尺寸和 ROI 尺寸按调用方实际输入处理，不设置 32 像素等额外下限。
- 尺寸信息只用于构造性能测试场景，不作为限制合法输入的依据。
- 对模板大于搜索图像、空 ROI、越界 ROI 等无法执行的输入返回明确错误，不静默改成另一组参数。

### 3.5 分层金字塔搜索

- 支持可配置层数的金字塔搜索，在粗层筛选候选，在细层完成精化。
- 金字塔实际可用层数由配置、模板尺寸和搜索区域共同确定。
- 粗细分层只作为加速手段，最终结果仍需满足本期精度要求。

### 3.6 亚像素定位

- 定位精度目标为 1/8 像素，对应 Sapera SubPixResolution 的 8 档语义。
- 可在整数命中点邻域采用二次曲面拟合或等效方法细化坐标，输出浮点结果。
- 精度验收以第 9 节规定的测试集和判定条件为准。

### 3.7 多目标定位

- 支持在一幅图像中定位多个相同目标，并返回 Top-N 个最佳匹配。
- 每个结果包含 x、y、angle、scale、score，分别表示模板中心位置、角度、缩放和匹配分数。
- 支持邻近命中去重，避免同一目标重复占用结果名额。
- 结果默认按分数从高到低排列，分数相同时使用稳定的次级排序规则。

## 4. 接口设计要求

- 将角度、尺度、ROI、分数阈值、Top-N、金字塔等参数集中放入配置结构，减少分散的初始化和 Set/Get 调用。
- 提供一次配置或初始化入口，以及独立的搜索执行入口。模型数据在初始化或预处理阶段生成。
- 搜索结果使用 `LocatorResult` 结构表达，字段为 `double x, y, angle, scale, score`。
- 图像格式、行跨度、坐标原点、角度方向、尺度定义和结果排序规则必须在公共头文件及使用说明中写清楚。
- 对非法参数、无效图像和不支持的处理组合返回可诊断的错误信息。
- 独立定位任务应能通过 OpenMP 并行执行，并行时不得修改其他任务的数据。

## 5. 算法设计方向

　　处理链由图像校验、模板预处理、金字塔构建、粗层候选搜索、细层精化、亚像素定位、邻近去重和排序输出组成。实现可以根据原型和性能分析调整，不要求逐项照搬 Sapera。

- NCC 计算：优先复用模板预计算结果，并评估积分图、滑窗点积等加速方式。
- 旋转与缩放：按配置生成搜索候选，粗层扫描和细层精化不得改变调用方要求的范围与步进语义。
- 多目标：结合分数阈值和邻近抑制筛选结果，再按分数排序输出 Top-N。
- 内存：复用线程内缓冲区，减少搜索热路径中的动态分配和重复初始化。
- 并行：批量定位任务以 OpenMP 做任务级并行。单任务内部是否继续并行由实测决定，避免线程嵌套造成额外开销。
- GPU：批量任务应打包上传并集中计算，复用流和显存工作区，减少逐任务传输与同步。模板统计按任务预计算，不得通过减少候选、降低亚像素档位或缩小搜索范围换取速度。优化前后必须通过相同的精度与鲁棒性回归。
- SIMD：先通过性能分析确认热点，再决定是否增加 AVX2 等优化，同时保留通用源码路径。

## 6. MFC 演示与评估工具

　　MFC 工具属于本期重要交付，既用于演示，也用于开发期间的正确性检查、性能测试和参数试验。工具中的所有定位结果必须来自核心算法源码。

### 6.1 图像与模板操作

- 加载图片时检查原始格式，只接受有效的 8 位单通道图片，不静默转换彩色图片。加载失败保留当前有效输入。
- 模板只通过单独加载图片指定，不再提供大图框选模板。
- 显示当前模板和搜索图像，保留鼠标框选、设置和清除 ROI，红框与核心配置保持一致。定位结果区不提供数值 ROI 输入框或“应用 ROI”按钮。
- 搜索图和模板支持缩放、平移和当前像素坐标提示，各种显示比例下框选均使用原图坐标。图像、结果框、中心点、标签和 ROI 必须裁剪在各自图像控件客户区内，不得覆盖其他界面区域。
- 提供单次工作区复位，恢复当前图片对刚加载齐全时的图片、路径、参数和后端，清除 ROI、旧结果和叠加，不自动搜索，不修改批量设置。

### 6.2 参数设置与单次搜索

- 设置角度范围、角度步进、缩放范围、缩放步进、金字塔层数、亚像素档位、分数阈值、Top-N 和邻近去重参数。参数错误指出具体字段和有效范围。
- 单次搜索在后台线程执行，窗口保持响应，冲突操作受控。结果通过界面线程消息一次性提交，输入在执行期间保持不变。
- 显示耗时、实际配置摘要和定位结果列表。开始新搜索及失败时清除旧结果，异常转换为明确中文错误。
- 在搜索图像上叠加带序号的结果框、模板中心点、角度、缩放和分数。列表选择高亮对应结果，标签不得重叠或超出图像控件。

### 6.3 批量测试与性能评估

- 使用系统目录选择器指定 Thick 数据目录，显示实际配对数和任务循环复用规则。首次打开选择器定位当前工程根目录，之后定位上次成功选择的目录，关闭并重启程序后仍保留记忆。当前输入框中已填写有效目录时优先定位该目录。记忆保存为绝对路径，标准 Release 程序存放于 `build/x64/Release/` 时按可执行文件位置向上三级定位工程根，不能依赖启动时的工作目录。记忆失效时回退工程根，配置写入失败须明确提示。
- 批量页显示实际生效的搜索配置和 ROI 来源。未明确启用 ROI 时使用完整图像。
- 支持并行线程数、后台执行、进度显示和任务边界取消。开始、失败和取消不得让旧统计冒充本次结果。
- 分别统计执行成功、无匹配和执行错误，支持查看全部结果及按状态筛选。MFC 不提供结果 CSV、原始耗时导出或固定基准入口。
- 普通批量完成后，点击任一结果行都要显示该任务的搜索图和对应模板。成功任务显示该任务的全部匹配框并高亮当前行对应的匹配项，无匹配及执行错误任务不保留旧匹配框。筛选后仍须按任务和匹配序号正确联动，不得只更新选中样式。
- 控制台固定基准执行 500 个任务，预热 5 轮、记录 50 轮，报告预处理、搜索、整体耗时、单任务均值、P99 和整体中位数，保存逐轮原始数据及首轮初始化信息。此性能验证流程不属于 MFC 界面。
- 批量测试与单次搜索使用同一套参数校验和搜索接口。批量取消扩展内部任务调度，不改变公共接口和既有 CUDA 分组优化。
- MFC 相同目录、任务数和配置的连续批量执行复用常驻会话，第二轮起预处理耗时为 0。任一输入或配置变化时重建会话，不增加新的界面控件。

### 6.4 界面布局与视觉要求

- 界面采用已确认的桌面工作台方案。左侧上部为搜索图和模板，下部为定位结果。右侧使用原生页签分隔“搜索参数”和“批量评估”，切换页签时保留左侧图像、模板和结果。
- 顶部只保留紧凑标题、产品说明及 CPU/GPU 后端选择。图像工具按钮按宽度均分，窄窗口换成两行。搜索参数页的角度、尺度和精度区域，以及批量页的数据目录、执行设置和统计结果区域，使用带标题的原生分组框形成完整边界，不再只用单条横线分隔。保留现有控件和操作位置关系，不增加装饰卡片或界面库。
- 每个功能组和输入项应直接说明用途、单位或有效取值。尺度说明为模板缩放倍率且 1 为原始尺寸，角度说明单位及顺时针方向，亚像素、最低分数、Top-N、去重半径、任务数和线程数均需有简明注释。
- 中文界面使用 Microsoft YaHei UI。参数值、坐标、耗时和统计数字使用 Consolas。普通标签和次要按钮保持正常字重，主操作使用青色实心按钮，匹配结果使用绿色，不使用装饰渐变。
- 窗口可拖动边框缩放、最大化和还原。根据当前客户区重新计算所有可见控件的位置与尺寸，分组框与内部控件使用同一套布局坐标并同步重绘，输入框和按钮随检查器宽度伸缩，图像与结果列表优先使用新增空间。移动或缩放子控件时不得把旧位置的像素复制到新位置，须清除透明文字及输入框边界的历史残影。编辑框四边须清晰可见，布局和页签切换完成后最后重绘其非客户区边框。
- 下拉菜单保留完整弹出高度。亚像素的 1、2、4、8 四档均须可见、可选择并传入实际配置。任务数和线程数输入框须能直接编辑，不得只显示数值而缺少可操作边界。
- 1180×720 客户区为最低可读布局基线。不得裁切文字、遮挡控件或清空参数、图像、结果和批量统计。分组框标题不得覆盖内部标签、输入框和列表。原生页签需要支持鼠标、Tab 键和方向键，焦点清楚。
- 结果列按列表实际宽度分配。批量统计使用标签和值两列对齐，保留任务数量、失败数量、预处理均值、搜索均值、整体均值、P99 和总耗时，失败任务仍在左侧结果列表显示。
- 不引入新的界面库。通过实际对话框的边框命中、最大化、反复页签切换、尺寸变化、长短文字替换、文字完整性、区域关系和真实窗口像素截图验收。除程序内消息回归外，还须用桌面实际输入拖动两个页签的窗口边框、滚动两个图像区、展开下拉菜单并直接编辑输入框，验看最终像素和实际值。图像必须保持原始比例与方向，不得出现拉伸、倾斜、越界或旧内容残留。
- 控制台测试程序双击运行后保留测试结果，等待用户按键关闭。带测试参数的命令行运行不增加等待，避免阻塞自动化。

## 7. 测试数据与性能目标

### 7.1 真实测试数据

- 数据位于 `test_data/Search/`。
- `Thick_<编号>.bmp` 是待匹配搜索图像，`Thick_<编号>_Kernel.bmp` 是对应定位核，两者按相同编号配对。
- 已核对编号 0～196，共 197 对完整数据，没有缺失配对。
- 搜索图像均为 118×118、8 位未压缩 BMP，定位核均为 48×48、8 位未压缩 BMP。
- 测试程序需要记录所用数据、参数和版本，保证结果可以复现。

### 7.2 性能目标与口径

- 目标场景为 500 个定位核与对应搜索图像的并行匹配，在 i7-12700K、32 GB 内存测试机上使用 OpenMP，总耗时目标为 20 ms 以内。
- 20 ms 来自既有估算，属于待实测验证的性能目标，不作为已经测得的结果。
- 当前有 197 对真实数据。197 对全量回归与 500 任务压测应分别报告，500 任务压测的任务组成在开发设计文档中明确，不能写成已有 500 对独立真实数据。
- 性能验收必须固定 ROI、角度与缩放组合数、线程数以及计时边界。
- CPU 与 GPU 性能分别报告。GPU 计时包含必要的数据上传、下载和同步，并记录 GPU 型号、驱动、运行时和后端版本。
- 性能报告分别记录模板预处理耗时、搜索执行耗时和整体耗时，并给出单任务均值、P99 和总耗时。
- 若实测未达到目标，应先依据性能分析调整算法和实现，不擅自删减已确认功能。

## 8. 本期不做的事项

- 24 位彩色图匹配。
- 边缘特征模板匹配。
- 模板遮罩（Mask）。
- 额外的亮度和对比度适应功能。NCC 本身仍按既定算法实现和验证。
- Blob、OCR、标定及其他 Sapera 模块。
- 免重编译替换、Sapera ABI 兼容、接口逐字一致和业务代码零改动。
- 静态库、动态库及其他预编译二进制交付。
