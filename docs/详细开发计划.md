## 2. 全局约束

- 核心算法只交付 `.h`、`.cpp` 等源代码，不交付静态库、动态库或其他预编译二进制。
- 核心代码不得包含 MFC、Windows API 或 Sapera 依赖，不得要求与 Sapera 的接口或 ABI 兼容。
- 验证环境为 Windows 10、Visual Studio 2019，语言标准栏保持默认，不强制 `/std:c++17`。
- 算法实现不限于 OpenCV，可自主开发或选用合适的开源实现，以速度、精度和鲁棒性实测为选型依据。若使用 OpenCV，版本必须为支持 VS2019 的 4 或更高版本，首次构建时记录实际版本和包含目录、库目录配置。
- 引入新的开源依赖前，记录来源、版本、许可证、使用范围和 VS2019 兼容性，不复制来源不明的代码。
- 核心算法以 CPU 和 GPU 双后端为目标。CPU 是通用基线，GPU 采用条件编译，不得让仅使用 CPU 的环境依赖 GPU SDK 或运行时。
- GPU 路径须加速核心匹配计算，可以采用 GPU 与 CPU 协同实现。GPU 不可用时返回明确错误，不静默回退为 CPU。
- 输入只支持 8 位单通道灰度图。24 位彩色、Mask、边缘匹配、Blob、OCR 和标定均不在本期范围内。
- x、y 是模板几何中心在搜索图像中的位置，中心按 `(width - 1) / 2`、`(height - 1) / 2` 计算。
- x 向右、y 向下，正角度为顺时针，`scale = 1` 表示模板原始尺寸。
- 模板、搜索图和 ROI 不设置 32 像素等额外下限，非法输入返回错误，不静默改变用户参数。
- 并行优化不得修改其他任务的数据。没有 OpenMP 时保留串行路径。
- 代码注释、MFC 提示、测试输出和集成说明使用中文。

## 4. 公共接口约定

　　后续任务不得随意更改以下名称。确需调整时，先更新本节、依赖任务和需求文档。

```cpp
// include/Locator.h
enum class LocatorError {
    Ok = 0,
    InvalidImage,
    InvalidConfig,
    InvalidRoi,
    NotInitialized,
    BackendUnavailable,
    InternalError
};

enum class LocatorBackend {
    Cpu = 0,
    Gpu
};

struct LocatorImage {
    const unsigned char* data;
    int width;
    int height;
    int stride;
};

struct LocatorRect {
    int x;
    int y;
    int width;
    int height;
};

struct LocatorConfig {
    LocatorBackend backend = LocatorBackend::Cpu;
    bool useRoi = false;
    LocatorRect roi = { 0, 0, 0, 0 };
    double angleMinDeg = 0.0;
    double angleMaxDeg = 0.0;
    double angleStepDeg = 1.0;
    double scaleMin = 1.0;
    double scaleMax = 1.0;
    double scaleStep = 0.01;
    int pyramidLevels = 1;
    int subPixelResolution = 8;
    double minScore = 0.0;
    int maxResults = 1;
    int xVicinity = 0;
    int yVicinity = 0;
};

struct LocatorResult {
    double x;
    double y;
    double angle;
    double scale;
    double score;
};

class Locator {
public:
    Locator();
    LocatorError initialize(const LocatorImage& model, const LocatorConfig& config);
    LocatorError execute(const LocatorImage& search,
                         std::vector<LocatorResult>& results) const;

private:
    struct State;
    std::shared_ptr<State> state_;
};
```

```cpp
// include/BatchLocator.h
struct BatchTask {
    int id;
    LocatorImage model;
    LocatorImage search;
    LocatorConfig config;
};

struct BatchResult {
    int id;
    LocatorError error;
    std::vector<LocatorResult> matches;
    double preprocessMs;
    double searchMs;
    double totalMs;
};

std::vector<BatchResult> executeBatch(const std::vector<BatchTask>& tasks,
                                      int threadCount);
```

　　补充语义：

- 图像指针和行跨度由调用方管理，生命周期必须覆盖当前调用。批量任务需覆盖整个 `executeBatch`。
- `execute` 进入时清空 `results`。没有满足阈值的结果时返回 `Ok` 和空数组，不把无匹配当作内部错误。
- `backend` 默认 `Cpu`。选择 `Gpu` 后，环境或后端不可用时返回 `BackendUnavailable`，不自动回退为 CPU。CPU 与 GPU 结果允许存在浮点舍入差异，但都必须满足同一套精度与鲁棒性验收。
- `subPixelResolution` 支持 1、2、4、8，默认 8。`maxResults >= 1`，`minScore` 位于 0～100。
- `pyramidLevels >= 1`。配置层数超过图像实际可计算层数时返回 `InvalidConfig`，不静默减少层数。
- `xVicinity`、`yVicinity` 是中心点邻近抑制半径，单位为像素，必须大于或等于 0。
- NCC 原始值映射为 `max(0.0, ncc) * 100.0`，最终按分数降序、x 升序、y 升序、angle 升序、scale 升序排列。
- `threadCount <= 0` 时使用 OpenMP 默认线程数。串行构建使用 1。批量结果按输入任务顺序返回。

## 7. 重点审查场景

- 非连续图像和带行跨度 ROI：不得把 `width` 当作 `stride`，由 T03、T04 的填充行测试覆盖。
- 常量模板、全零搜索图和 NCC 分母为零：不得崩溃或返回 NaN，由 T03 覆盖。
- 角度、尺度端点不能整除步长及旋转后模板越界：不得死循环或静默改参数，由 T06、T07 覆盖。
- 重复纹理、同分候选和相邻目标：排序必须稳定，去重不得误删不同目标，由 T04、T09 覆盖。
- 并行任务的数据生命周期、结果顺序和耗时统计：不得出现数据竞争、结果错位或把 197 对数据写成 500 对，由 T10 覆盖。
- CPU/GPU 结果一致性、GPU 不可用错误和传输计时：不得静默回退、降低精度或漏计数据传输与同步，由 T11 覆盖。
