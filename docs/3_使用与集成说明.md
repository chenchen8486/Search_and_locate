# 搜索匹配定位库使用与集成说明

## 1. 交付范围

　　本项目提供 8 位单通道灰度图的 NCC 模板匹配源码，支持 ROI、多角度、多尺度、金字塔、亚像素、Top-N 和邻近去重。CPU 是默认后端，CUDA 后端通过条件编译启用。MFC 工具与控制台测试直接编译同一套核心源码。

　　项目不提供核心静态库、动态库或预编译二进制。24 位彩色图、Mask、边缘匹配、Blob、OCR 和标定不在本期范围内，也不要求 Sapera 接口或 ABI 兼容。

## 2. 环境与依赖

- 已验证编译器为 Visual Studio 2019 16.11、v142 工具集，工程保持默认 C++14 语言模式。
- OpenCV 必须为支持 VS2019 的 4 或更高版本。本次实际使用官方 OpenCV 4.10.0、Apache-2.0、vc16 库。
- CPU 构建只依赖 OpenCV 和标准 C++ 运行环境。OpenMP 用于任务级并行，未启用 OpenMP 时保留串行实现。
- GPU 构建使用 CUDA Toolkit 11.4 和 NVIDIA 显卡。CUDA Toolkit 受 NVIDIA EULA 约束，不是开源视觉算法依赖。
- 本次实测显卡为 RTX 3070 Laptop 8 GB，并非需求基线中的 RTX 4060 12 GB。现有工程生成 compute 8.6 二进制和 PTX，RTX 4060 的兼容性仍需实机验证。
- MFC 工具需要 VS2019 的 MFC 和 ATL 组件。核心算法不依赖 MFC、Windows API 或 Sapera。

## 3. 源码加入方法

　　`loadGrayImage` 按原始解码格式只接受 `CV_8UC1`，不再把彩色图片静默转换为灰度。可选的错误字符串说明文件、解码或通道问题，加载失败不会修改输出图像。

　　将 `include/` 加入公共包含目录，将 `src/` 加入内部包含目录。CPU 工程加入以下源码：

```text
src/Locator.cpp
src/BatchLocator.cpp
src/NccMatcher.cpp
src/ResultRefiner.cpp
src/TransformSearch.cpp
src/PyramidSearch.cpp
```

　　`LocatorInternal.h` 和其他 `src/*.h` 是内部头文件，随源码一起保留。使用批量接口时，公共头文件为 `include/Locator.h` 和 `include/BatchLocator.h`。测试和 Thick 数据工具还需要 `tools/BatchData.cpp`。

　　CUDA 工程除上述文件外，还要加入 `src/gpu/CudaMatcher.cu`，保留同目录的 `CudaMatcher.h`，并定义 `LOCATOR_WITH_CUDA`。编译器需将 `.cu` 交给 NVCC，链接 `cudart.lib`。仅使用 CPU 时不要加入 `.cu`，也不要定义该宏。

## 4. Visual Studio 2019 构建

　　在 VS2019 的 x64 本机工具命令提示符中，从工程根目录执行。OpenCV 路径由 `OpenCVRoot` 指定，也可以使用工程属性表支持的 `OPENCV_DIR` 环境变量。

```bat
msbuild Locator.sln /m /p:Configuration=Debug /p:Platform=x64 /p:OpenCVRoot="C:\opencv\build"
msbuild Locator.sln /m /p:Configuration=Release /p:Platform=x64 /p:OpenCVRoot="C:\opencv\build"
```

　　默认 `EnableCuda=false`，不需要 CUDA SDK，也不链接 CUDA 运行时。启用 CUDA 时执行：

```bat
msbuild Locator.sln /m /p:Configuration=Release /p:Platform=x64 /p:EnableCuda=true /p:OpenCVRoot="C:\opencv\build"
```

　　`tools/Cuda.props` 默认从 `CUDA_PATH` 取得工具包路径。非默认安装位置可增加 `/p:CudaToolkitRoot=实际路径`。本机使用的 CUDA 11.4 集成文件位于工具包的 `extras/visual_studio_integration/MSBuildExtensions/`。其他 CUDA 版本需要同步调整属性表中的版本路径，并重新验证 VS2019 兼容性。

　　MFC 工程默认使用 Visual Studio 安装目录下的 ATLMFC。需要显式指定本地依赖时，可覆盖 `MfcRoot` 和 `MfcRuntimeDir`。这些路径属于构建环境，不是核心库的交付依赖。

　　输出位于 `build/x64/<配置>/`，中间文件位于 `temp/obj/`。临时测试输出只能放在 `temp/`。`reference/` 和 `test_data/` 是只读资料和数据目录。

## 5. 接口语义

### 5.1 图像和生命周期

　　`LocatorImage` 接收图像指针、宽、高和行跨度，只接受 8 位单通道数据。`stride >= width`，支持非连续行。调用方保证输入内存在当前调用期间有效，批量任务的数据需覆盖整个 `executeBatch`。

　　`Locator::initialize` 保存模板及变换结果。模板初始化与搜索执行分开，变换模板和模板金字塔不会在每次搜索时重新生成。同一个 `Locator` 可重复执行，批量执行时为每个任务创建独立定位器。

### 5.2 坐标、角度和尺度

- x 向右、y 向下，结果 x、y 是模板几何中心在搜索图中的连续坐标。
- 模板中心按 `(width - 1) / 2`、`(height - 1) / 2` 计算，偶数尺寸可以产生半像素中心。
- 正角度表示顺时针，角度单位为度。`scale = 1` 表示原始尺寸。
- ROI 使用原图像素坐标，返回结果同样使用原图坐标。
- 亚像素档位只支持 1、2、4、8。整数候选在局部使用模板重采样和 CPU NCC 精化。

### 5.3 后端

　　`LocatorConfig::backend` 默认为 `LocatorBackend::Cpu`。选择 `LocatorBackend::Gpu` 后，整图 NCC 和金字塔粗层 NCC 在 CUDA 上执行，模板变换、候选筛选和亚像素局部精化留在 CPU。批量执行对单层、无 ROI、单角度、单尺度任务按 4 个一组打包上传、计算和下载，不同工作组可重叠执行 GPU 与 CPU 阶段，其他配置保留逐任务 CUDA 路径，不回退 CPU。CUDA 流和显存工作区按线程复用，尺寸增大时扩容，线程退出时释放。CUDA 计时包括必要的上传、下载和同步，首次分配在基准预热中完成。批量的单任务搜索耗时包含该组 GPU 耗时的均摊值及本任务精化耗时。

　　GPU 后端在构建未启用 CUDA 或没有可用设备时返回 `BackendUnavailable`，不会自动改用 CPU。CUDA 执行失败返回 `InternalError`。

### 5.4 结果与错误

- NCC 原始值按 `max(0.0, ncc) * 100.0` 转为 0～100 分。
- 结果按分数降序、x 升序、y 升序、角度升序、尺度升序排列。
- `maxResults >= 1`，`xVicinity` 和 `yVicinity` 是中心点邻近抑制半径，单位为像素。
- 没有满足阈值的结果时返回 `Ok` 和空数组。`execute` 进入时清空旧结果。
- 常量模板返回 `InvalidImage`。全零搜索图正常结束并返回空结果。
- 非法参数返回 `InvalidConfig`，空、越界或小于模板的 ROI 返回 `InvalidRoi`。
- 模板大于搜索区域时返回 `InvalidImage` 或 `InvalidRoi`，未初始化执行返回 `NotInitialized`。

## 6. 最小示例

```bat
build\x64\Release\LocatorExample.exe
build\x64\Release\LocatorExample.exe --gpu
```

　　默认命令执行 CPU 搜索，`--gpu` 请求 CUDA 后端。示例检查初始化错误、执行错误、空结果和预期坐标。完整代码位于 `examples/MinimalExample.cpp`。

## 7. 测试和真实数据

　　将真实数据放在 `test_data/Search/`，保持 `Thick_<编号>.bmp` 和 `Thick_<编号>_Kernel.bmp` 的配对命名。从工程根目录运行：

```bat
build\x64\Release\LocatorTests.exe --suite core
build\x64\Release\LocatorTests.exe --suite synthetic
build\x64\Release\LocatorTests.exe --suite all
build\x64\Release\LocatorTests.exe --suite performance
build\x64\Release\LocatorTests.exe --suite gpu
```

　　双击 `LocatorTests.exe` 相当于执行无参数的全量 CPU 回归，结束后会显示“按回车键关闭窗口”，便于直接查看结果。在命令行中运行上述带参数命令时不会等待输入。

　　`--suite all` 是 CPU 回归，不依赖 GPU。`--suite gpu` 包含 GPU 边界、CPU/GPU 一致性、串并行一致性、100 组合成回归、197 对真实数据回归和 500 任务性能测试。没有可用 GPU 时测试会明确报告后端不可用。

　　500 任务基准重复使用 197 对独立图像，固定 Release x64、20 线程、完整图、角度 0、尺度 1、金字塔 1、亚像素 4、Top-N 1，预热 5 轮、记录 50 轮。CPU 和 GPU 原始计时分别写入 `temp/t10_benchmark500.csv` 和 `temp/t11_gpu_benchmark500.csv`。当前基准于 2026-11-06 按用户要求由 1/8 改为 1/4，公共接口的默认亚像素档位仍为 8。

## 8. MFC 演示工具

　　启动 `LocatorMfc.exe` 后，分别加载搜索图和小图模板。模板不再支持从搜索图框选。设置 ROI 后执行单次搜索，界面显示结果框、中心点、角度、尺度、分数和耗时。

　　搜索图和模板加载齐全后，“复位（初始状态）”恢复该图片对加载时的图片、路径、搜索参数和后端，清除 ROI、结果及叠加，不自动搜索，也不修改批量目录、任务数、线程数或统计。图片对不完整时按钮禁用，重新加载一对图片后保存新基准。

　　搜索图和模板均支持滚轮以光标为中心缩放，搜索图支持中键拖动平移。标题区显示原图坐标与缩放比例，ROI 和结果叠加使用相同的原图坐标换算。图像、结果框、中心点、标签和 ROI 均裁剪在各自图像控件内，加载新图或复位恢复整图适配视图。

　　ROI 通过“设置 ROI”后在搜索图上拖动鼠标框选，红框、执行摘要和核心配置保持一致。“清除 ROI”及复位会清空 ROI 和红框。定位结果区不提供数值 ROI 输入框或“应用 ROI”按钮。

　　主窗口支持拖动边框调整大小，也支持最大化和还原。图像与结果列表使用新增空间，右侧检查器随窗口扩展，顶部后端下拉框保持固定宽度。最小客户区为 1180×720，工具按钮在空间不足时换成两行。缩放和切换页签不会清空参数、图像、匹配结果或统计。

　　顶部后端下拉框提供 CPU 和 GPU。右侧使用“搜索参数”和“批量评估”原生页签，选中项以青色高亮，支持鼠标、Tab 键和方向键。参数值和结果数字使用 Consolas，亚像素档位通过下拉框选择 1、2、4、8。角度、尺度和去重参数旁有单位及用途说明。执行按钮上方动态显示实际角度、尺度和 ROI 摘要，参数编辑、ROI 变化及复位时同步更新。

　　搜索参数页的角度范围、尺度范围、精度与结果，以及批量页的数据目录、执行设置、统计结果均有带标题的完整分组框。分组框与内部控件同步缩放和重绘，用于辨认功能归属。

　　批量页常驻显示后端、角度、尺度、金字塔、亚像素、最低分、Top-N、去重半径及 ROI。摘要来自当前实际控件和单次 ROI 设置，未启用 ROI 时使用完整图像。

　　批量评估在后台准备数据并执行，显示已完成任务数。“取消”在每个 CPU 任务或四任务 CUDA 分组的边界生效，只保留已完成结果。开始、失败或取消时旧统计失效。关闭窗口会等待已启动工作结束并清理完成消息。公共 `executeBatch` 签名及原有 CUDA 分组路径不变。

　　“选择目录”使用 Windows 原生目录浏览框，不需要选择具体文件。首次打开定位当前工程根，后续定位有效输入目录或上次成功选择的目录。取消选择不改变记忆，重启程序后从程序旁的 `LocatorMfc.ini` 恢复上次目录。配置写入失败会明确提示，但不影响本次选择。标准 Release 按可执行文件位置向上三级识别工程根，不依赖启动目录。相对目录也按工程根解析。未保存过目录时编辑框显示 `.`。

　　扫描后显示实际配对数，任务数为 0 时执行全部真实配对。任务数大于配对数时明确提示按编号循环复用。结果列表保留全部任务及每个匹配的完整字段，可按全部、成功、无匹配、执行错误筛选。统计区分别显示成功、无匹配和执行错误，保留预处理均值、搜索均值、整体均值、P99 和总耗时。MFC 不提供结果 CSV 或原始耗时导出入口。

　　点击任一普通批量结果行，左侧会显示该任务的搜索图、模板和图片路径。成功任务显示全部匹配框并高亮当前行对应的匹配项，无匹配和执行错误任务不保留旧匹配框。筛选及循环复用任务仍按行内任务编号和匹配序号联动。对话框保留本次输入图像供结果审查，开始下一次批量或关闭窗口时释放。浏览结果不会覆盖显式加载图片时保存的单次复位基准。

　　单次结果列表包含序号、中心、角度、尺度和分数。选择列表行会高亮对应的图像结果，标签带相同序号并自动避让和限制在图像控件内。

　　参数格式或范围错误会指出具体字段和有效范围，并聚焦、选中对应输入框。编辑框四边完整显示，亚像素下拉框保留完整列表高度，1、2、4、8 四档均可展开选择。

　　单次搜索在后台线程执行，输入图片和配置在执行时复制，结果由界面线程消息一次提交。搜索期间可调整窗口和切换页签，加载、复位、ROI、参数和重复执行等冲突操作暂时禁用。窗口关闭会等待已启动搜索结束。开始新单次搜索、参数格式错误或核心执行失败时，旧结果列表、结果框和中心点都会清除。单次工作流统一捕获 OpenCV、标准及未知异常，返回内部错误并在状态栏保留异常来源与原始诊断信息。

　　对话框通过 `mfc/LocatorWorkflow.cpp` 执行初始化和搜索，单次与批量共用该工作流。无需操作窗口即可验证这条实际调用路径：

```bat
build\x64\Release\LocatorMfc.exe --self-test "test_data\Search"
build\x64\Release\LocatorMfc.exe --self-test "test_data\Search" --preview "temp\t40_final.png"
```

　　MFC 不提供固定基准入口。控制台通过 `LocatorTests.exe --suite performance` 和 `--suite gpu` 执行 500 任务、预热 5 轮、记录 50 轮，参数为完整图、角度 0、尺度 1、金字塔 1、亚像素 1/4、Top-N 1。逐轮原始耗时保存为带 BOM 的 UTF-8 CSV，具体路径见第 7 节。

　　`--preview` 是可选项。程序通过与正常启动相同的 `DoModal` 创建窗口，在程序控制下显示并重绘窗口，直接读取客户区的实际像素。保存默认参数页、1180×720 紧凑布局和批量统计页，文件名分别为指定路径、`.compact.png` 和 `.batch.png` 后缀。另外保存 93×37 非对称模板探针及最小窗口连续三轮页签切换截图。程序内自测不代替桌面实际操作。

　　自测要求目录中有完整的 197 对真实数据，依次执行 CPU 和 GPU 的 Thick_0 单次搜索、197 对批量搜索，并比较位置、角度、尺度和分数。程序设置非默认参数，检查页签互斥、鼠标通知、方向键、参数保留、控件映射、结果列表、两列统计和旧结果清理，还覆盖边框命中、最大化、扩大、缩小与还原。批量选择检查使用真实列表通知，核对普通、筛选、无匹配和错误行的图像、路径、ROI 和匹配索引。六个功能分区同时检查原生分组框、内部控件包含关系及重绘。父窗口隐藏时按子控件的 `WS_VISIBLE` 样式判断页面显隐，避免把离屏状态误判为隐藏页面。

　　`--preview` 还会逐像素检查图像路径和状态文字清除后的背景，验证 93×37 探针的取样值，检查最小窗口页签保持单行且位于客户区内。两个页签各连续执行 12 轮尺寸变化，检查分组空白区和输入框底部没有旧边框残留，保存 `.resize-pixels.png` 和 `.batch-resize-pixels.png`。新增图像放大后的外部像素检查、输入框四边检查和亚像素原生弹出列表截图，后缀分别为 `.zoom-clipping.png` 和 `.dropdown.png`。

　　除程序内自测外，T38～T40 已使用桌面实际输入验证目录选择及记忆、两个页签的边框拖动、最大化和还原、单次及批量结果联动、两个图像区滚轮缩放、亚像素逐项选择和批量输入编辑。相关验收记录见 `docs/4_测试报告.md`，最新界面截图使用 `temp/t40_live_search.png` 和 `temp/t40_live_batch.png`。

　　成功时返回退出码 0，失败时返回非零值。CPU-only 构建应使用 `LocatorTests.exe --suite all`，不需要执行需要 GPU 的完整自测。自测不主动弹出错误对话框，核心错误码由控制台用例覆盖。

　　实际结果和当前未达标项见 `docs/4_测试报告.md`，开发过程记录见 `docs/2_详细开发计划.md`。
